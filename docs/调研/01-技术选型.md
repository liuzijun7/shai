# 01 技术选型：用什么做、怎么让大家连上

> 调研时间：2026-11-14 至 11-15。版本号、价格、能否从国内访问，都是当时查到的。标了“未能核实”的地方是没找到一手来源。

## 一句话结论

这个游戏不需要专门的“游戏引擎”。建议这样搭：

- 规则继续用刘同学写的 Python 规则引擎，放在一台服务器上跑；
- 玩家不装任何东西，用浏览器打开一个网址就能玩；
- 网页用普通网页技术画界面和出招动画；
- 服务器租一台香港的小型云主机，每月约 6 美元，国内和加拿大都能连。

下面先讲几个概念，再讲每一项为什么这么选。

## 1. 先讲三个概念

### 1.1 “游戏引擎”是什么

游戏引擎是一套现成的工具箱。它替你做这些事：每秒几十次地重画画面、物理碰撞、播放动画和声音、管理图片等资源、打包成手机或电脑上能装的程序。常见的有 Unity、Godot、Cocos Creator、Phaser。

游戏引擎主要解决的问题是“画面上一直有很多东西在动”。我们这个游戏是回合制的：每回合双方各点一个按钮，然后播一小段动画，再更新血条。画面上大部分东西是按钮、血条、文字和两张人物图。这些正好是网页本身擅长的。

一个有说服力的例子：Pokémon Showdown（全球最大的宝可梦对战网站，代码公开）没有用任何游戏引擎，战斗画面就是普通网页元素加动画。

### 1.2 一个联机游戏由三块组成

| 名字 | 它管什么 | 在我们这里 |
|---|---|---|
| 规则引擎 | 只管规则：谁出了什么招、伤害多少、状态怎么变。不管画面 | 刘同学的 `engine.py` 和 `game_data.py`，已经有了 |
| 服务器 | 一台一直开着的电脑。管登录、开房间、收两边的选招、调用规则引擎、把结果发给两边 | 还没有 |
| 客户端 | 玩家看到和操作的界面。只负责显示和把玩家的选择发给服务器 | 现在只有一个本机测试用的窗口（`gui.py`），网页版还没有 |

这种“所有结果都由服务器算，客户端只显示”的做法叫**权威服务器**。好处有两个：两边看到的结果一定一样；没人能通过改自己电脑上的程序作弊。刘同学在 `扩展接口说明.txt` 里已经写了同样的思路。

### 1.3 用什么语言

- 规则引擎和服务器：Python。已经有 1200 行规则代码和 20 个自动测试，没有理由重写。
- 网页客户端：浏览器只认 JavaScript 这一种编程语言。TypeScript 是带类型检查的 JavaScript，写完会被转换成 JavaScript。界面的结构用 HTML 写，样式用 CSS 写。

## 2. 客户端画面：几种方案对比

| 方案 | 语言 | 现状 | 上手难度 | 玩家要下载多大 | 能否由 AI 直接写成文本文件 | 适合度 |
|---|---|---|---|---|---|---|
| 普通网页元素 + 网页自带的动画功能 | JavaScript / TypeScript | 浏览器自带 | 最低 | 0 | 完全可以 | 最合适 |
| PixiJS（一个用显卡画图的库） | 同上 | 8.23.0，2026-11 仍在更新 | 中等；不带按钮和文字排版 | 约 256 KB | 可以 | 适合以后加粒子特效，不适合做界面 |
| Phaser（网页游戏引擎） | 同上 | 4.2.1，2026-07 | 中等 | 约 353 KB | 可以 | 能用，大部分功能用不上 |
| Cocos Creator（国内常用的游戏引擎） | TypeScript | 3.8.8；新的 Cocos 4 已公布 | 高 | 未能核实 | 较差：场景要在可视化编辑器里拼 | 太重 |
| Godot 4 导出成网页 | GDScript | 4.7.2，很活跃 | 中等偏高 | 引擎文件几十 MB，首次打开慢 | 一半：文件是文本，但导出要用编辑器 | 太重 |
| Unity 导出成网页 | C# | Unity 6 | 最高 | 空项目也有几 MB 到十几 MB | 差：依赖编辑器 | 太重 |

Pokémon Showdown 的做法已核实：它的 `battle-animations.ts` 用网页里的图片元素表示特效，再用动画函数移动它们；每个招式的动画写在 `battle-animations-moves.ts` 这张大表里。

**建议**：用普通网页元素。以后想要粒子特效，再在上面叠一层 PixiJS。

## 3. 出招动画怎么做

你最担心的是这一块，所以多讲一点。业内从便宜到精致大致有七档：

1. **让静态的人物图自己动**：往前冲一下、抖一下、闪白、血条滑动。只要几行代码，不需要任何美术素材。
2. **飞行物 + 命中火花**：一张小图从出招者飞到对手身上，命中时放一张火花图。有免费素材可用：Kenney Particle Pack（完全放弃版权，可随意使用）；Pokémon Showdown 的 `fx/` 文件夹（大部分图片同样放弃了版权，个别除外）。
3. **逐帧动画**：把十几帧画在一张大图上轮流显示。要有人画。
4. **粒子特效**：很多小点按规则运动（火、烟、星星）。PixiJS 8 自带；另有免费的 Effekseer 特效编辑器。
5. **骨骼动画**：把人物切成头、手、身体等零件，用“骨头”带着动。工具 Spine 要钱（一次性 69 美元起），DragonBones 基本没人维护了。
6. **矢量动画文件**（Lottie、Rive）：要有人在专门软件里做。
7. **预先做好的视频或动图**：播放最简单，但每个招都得有人做。

原版 Flash 游戏的做法：从一份非官方反编译的赛尔号客户端代码能看到，它是每只精灵一个 Flash 文件、每个技能一个 Flash 文件，由美术在 Flash 里逐个做的。Q宠大乐斗的做法未能核实。我们没有美术团队，走不了这条路。

**建议**：给每个招式标一个“动画类型”（近身攻击、飞行物、光束、给自己加状态、给对手加状态、全场效果）和一个颜色。用第 1、2 档做出六七个通用动画函数，所有招式一出来就有动画。另留一张“专属动画表”，以后哪个招想做得更精致，就单独替换。Pokémon Showdown 就是这么组织的。

可选的补间动画库（帮你把“从 A 滑到 B”算得更顺滑）：anime.js 4.5.0 和 Motion 14.14.0 都是完全开源免费的；GSAP 3.15.1 现在也免费，但不是开源许可。浏览器自带的动画功能也够用，可以先不引入任何库。

## 4. 服务器和联网

浏览器和服务器之间要一条“双方随时都能发消息”的连接，这种连接叫 **WebSocket**。

| 方案 | 说明 | 评价 |
|---|---|---|
| 保留 Python 引擎，外面包一层 FastAPI（一个常用的 Python 网络服务库）提供 WebSocket | 引擎和服务器在同一个程序里；房间、断线重连要自己写几百行 | 最简单，推荐 |
| python-socketio | 自带房间、自动重连、消息确认；网页端要配套的库 | 备选 |
| Colyseus（Node.js 上的游戏房间框架） | 功能全，但规则引擎要用 JavaScript 重写 | 不值得 |
| boardgame.io（回合制桌游框架） | 能隐藏信息、能同时出招；但最后一次发布是 2022 年，只支持 JavaScript | 不建议 |
| Supabase、Firebase 这类托管后台 | 没地方跑我们的 Python 规则引擎；Firebase 在国内普遍被认为连不上 | 不适合 |
| Cloudflare 的边缘计算服务 | 只支持 JavaScript；它的默认域名在国内被屏蔽 | 不适合 |

**建议的最简可靠设计**：

- 一个 FastAPI 程序。房间放在内存里。用户和对战记录存进 SQLite（一个单文件的小型数据库）。
- 规则引擎向每个玩家开出“待办请求”：请选招；请出石头剪刀布。服务器等双方都答完才往下算，期间只告诉对方“他选好了”，不告诉选了什么。
- 所有随机数都在服务器上产生。
- 每次往外发数据前，按“这个玩家能看到什么”过滤一遍。
- 断线重连：网页保存一个会话凭证，重连后服务器把完整局面和未完成的请求重新发一遍。
- 账号：凭邀请码注册，用户名加密码，密码只存加密后的摘要。
- 前面放一个 Caddy（一个能自动申请加密证书的网页服务器），这样网址是 `https://` 开头的。

## 5. 部署：国内和加拿大都要能连

| 选项 | 价格 | 国内访问 | 备注 |
|---|---|---|---|
| 腾讯云轻量应用服务器，香港，2 核 2 GB | 6 美元/月 | 香港节点不需要备案 | **推荐** |
| 腾讯云轻量，新加坡或东京 | 4.2 到 5 美元/月 | 同上 | 更便宜，延迟略高 |
| 阿里云轻量，香港 | 文档示例为 3.5 美元/月，具体配置未能核实 | 同上 | 备选 |
| Vultr 或 Linode，东京 | 5 美元/月 | 各家线路质量未能核实，晚高峰可能变慢 | 备选 |
| 国内的服务器 | — | 最快 | 域名指向它就必须做 ICP 备案（向工信部登记网站），换端口也躲不开，审核要几天到几周。只用 IP 地址访问属于灰色地带，而且没法用正常的加密连接 |
| Vercel、Cloudflare Pages/Workers、Render | 有免费档 | 默认域名在国内被屏蔽或不稳定 | 不适合 |
| GitHub Pages | 免费 | 时好时坏，而且只能放静态网页，跑不了服务器 | 不适合 |
| Fly.io、Railway | 2 到 5 美元/月起 | 测试结果不一致 | 不建议 |

正式租服务器之前，可以先用“内网穿透”临时试玩（把你电脑上跑的服务器临时暴露给朋友）：

- cloudflared 临时隧道：有一次测试显示国内能连。
- Tailscale：官网国内能访问，但国内没有中转节点，直连不成功时会很慢。
- ngrok：最近的测试结果比较旧，不确定。

**主要风险**：跨境线路可能变慢，IP 或域名也可能在没有通知的情况下被屏蔽。所以部署要写成脚本，按月付费，出问题时一小时内能搬到另一个地区。租之前先用 itdog.cn 这类工具从国内测一下延迟。

## 6. 这一部分需要你拍板的地方

这些问题也收在《待确认问题》里：

1. 是否同意“Python 规则引擎 + 网页客户端”这个方向？另一条路是把规则用 TypeScript 重写，好处是以后可以离线单机玩，代价是丢掉刘同学现有的代码和测试。
2. 只在电脑浏览器上玩，还是手机也要能玩？这会影响界面排版。
3. 服务器谁来出钱、用谁的账号租？国内的朋友更方便注册腾讯云或阿里云。
4. 要不要买一个域名（每年几十到一百多元人民币，具体价格没查）？没有域名就只能用 IP 地址访问。
