# 02 开源实现调研：别人是怎么做回合制对战的

> 调研时间：2026-11-14 至 11-15。星标数、许可证、最后更新日期都来自 GitHub。下面每个仓库都实际打开看过；凡是推断而非直接读到的，都标了“推断”。

## 一句话结论

- **最值得学的是 Pokémon Showdown**。它把“服务器、规则引擎、客户端”分得很干净，而且它的结算过程能在回合中途停下来等玩家输入、再继续。我们的“贼”正需要这个能力。
- **赛尔号**没有官方开源。GitHub 上有两个爱好者写的战斗引擎值得看，它们展示了“魂印”这类被动效果怎么写成数据、挂在固定的时间点上。其余多是私服，带着官方资源，有法律风险，不要用。
- **Q宠大乐斗**没有任何公开的战斗引擎或招式动画代码。能找到的几乎都是给正版游戏自动做日常任务的脚本。

## 1. Pokémon Showdown（宝可梦对战网站）

| 仓库 | 语言 | 星标 | 许可证 | 说明 |
|---|---|---|---|---|
| [smogon/pokemon-showdown](https://github.com/smogon/pokemon-showdown) | TypeScript | 6028 | MIT（可自由使用） | 服务器 + 规则引擎 |
| [smogon/pokemon-showdown-client](https://github.com/smogon/pokemon-showdown-client) | TypeScript | 724 | 整体是 AGPL（用了它的代码就必须公开自己的源码）；其中战斗回放和动画部分是 MIT | 网页客户端 |

### 1.1 三层怎么分开

- 规则引擎（`sim/` 目录）完全不知道网络的存在。它的接口是一条文本流：往里写 `>p1 move 1`（玩家 1 用第 1 个招），它往外吐战斗记录。
- 服务器（`server/room-battle.ts`）把这条文本流包成一个“房间”，负责把消息转给对的玩家。
- 客户端不跑任何规则，只负责把战斗记录一行一行播成动画。

### 1.2 双方同时选招、互相看不到

- 引擎给每个玩家单独发一份“请求”，里面列出他这回合能用的招（哪些被禁用也标出来）。
- 玩家回一句很短的话，比如 `move 1`。
- 每份请求带一个编号。玩家如果回答的是旧请求，服务器直接拒收。这样不会因为网络延迟把上一回合的选择算到这一回合。
- 双方都答完之前，什么都不结算。
- 需要保密的信息，引擎会输出两个版本：一份给本人，一份给对手。

### 1.3 回合中途停下来等玩家（我们最需要的部分）

Pokémon Showdown 把一个回合拆成一串小动作排成队，一个一个执行。每执行完一个，检查“是否需要问玩家”。如果需要（例如精灵倒下了，要玩家选下一只上场），就停下，把还没执行的队列留着。玩家回答后，从留下的队列继续。

要注意：它只能在两个小动作之间停，不能在一个效果触发到一半时停。

### 1.4 谁先动

- 所有动作和被动效果用同一把尺子排序：先看动作类别，再看先制级别，再看速度，最后看几个细分顺序。
- 速度完全相同的时候，用可重现的随机数打乱。整个引擎只有这一个地方处理平局。
- 这一点对我们很有用：**我们只要把“平局时掷随机数”这一处换成“平局时双方贼”就行**（推断）。

### 1.5 被动效果怎么触发

- 引擎在固定的时间点广播事件，例如“出招前”“即将命中”“受到伤害后”“回合结束”。
- 每个特性、状态、道具都可以登记“我在某个事件上要做什么”，并带一个优先级数字。
- 处理函数的返回值有统一约定：不返回 = 继续；返回“否” = 取消这次行动；返回别的值 = 用它替换原来的数值（例如改伤害）。

### 1.6 战斗记录和动画

- 引擎输出的每一行是一个事件，例如 `|move|甲|火焰拳|乙`、`|-damage|乙|73/100`。
- 客户端取一行，更新自己记的局面，播对应动画，等动画播完再取下一行。
- 招式动画查一张大表；表里没有的招，就用“撞击”的通用动画。
- 引擎把每一条输入和随机数种子都存下来，所以任何一局都能原样重放。

### 1.7 更容易读的衍生项目

- [pkmn/ps](https://github.com/pkmn/ps)（TypeScript，153 星，MIT）：把 Showdown 拆成几个独立的包，想单独读规则引擎的话看这个最方便。
- [hsahovic/poke-env](https://github.com/hsahovic/poke-env)（Python，542 星，MIT）：用 Python 写对战机器人的接口，将来做电脑对手或强化学习时可以参考。

## 2. 赛尔号

### 2.1 值得看的两个战斗引擎

**[arcadia-eternity/arcadia-eternity](https://github.com/arcadia-eternity/arcadia-eternity)**（TypeScript，14 星，MIT，2026-11 仍在更新）

- 赛尔号 2（约瑟传说）的战斗模拟器。只有战斗：房间、匹配、配队。有网页客户端（Vue 3）和服务器（Express + Socket.IO）。
- 特性和纹章做成“印记”：数据文件里写这个印记引用哪些效果；每个效果由三部分组成，即什么时间点触发、满足什么条件、做什么，另带一个优先级数字。一共定义了 46 个触发时间点。
- 出手顺序：换人先于出招 → 技能先制 → 速度 → 原始顺序。没有随机，也就是说平局时固定某一方先。
- 只在选招和被迫换人时等玩家；回合结算是一口气算完的。
- 风险：它配套的资源仓库里是原版游戏素材，没有许可证。代码可以学，素材不能用。

**[deepdiver-997/simulation-battle-system](https://github.com/deepdiver-997/simulation-battle-system)**（C++，11 星，Apache-2.0，2026-10 仍在更新）

- 赛尔号对战引擎。把一个回合写成 41 个固定状态，引擎永远处在其中一个状态里，按固定规则走到下一个。
- 每个状态就是一个时间点。魂印被写成一串“在哪个状态、执行哪个函数、是否只触发一次”的登记项。
- 效果只负责把事件放进队列，由引擎在每个状态结束时统一处理。
- “谁先出手”集中在一个函数里：先看效果 → 道具 → 必定先手 → 先制级别 → 速度 → 随机。
- 引擎可以停在任何一个状态上等玩家输入，这一点比 Pokémon Showdown 更接近我们的需要。
- 仓库里不带官方数据，法律风险低。

**[Brady29655751/Seer2-Restart-Lite](https://github.com/Brady29655751/Seer2-Restart-Lite)**（Unity，42 星，没有许可证）

- 单机版赛尔号 2 同人重制。效果写成表格的一行：时间点、优先级、目标、条件、能力。
- 出手顺序：动作类型 → 特殊先制 → 先制 → 速度 → 随机。
- 没有许可证，并且仓库很大，推断带了原版美术资源。只适合看思路。

### 2.2 私服（都有法律风险，仅作了解）

- [niaohao/niaogo](https://github.com/niaohao/niaogo)（Go）：老版本赛尔号服务器，技能效果是按官方效果编号一个个写死的，没有魂印，带官方数据表，需要原版客户端。
- [72wo/Seer-golang](https://github.com/72wo/Seer-golang)（Go）：只有打野怪的战斗，出手顺序是先制再速度，带官方数据。
- [hex3f/Reseer](https://github.com/hex3f/Reseer)：2.3 GB，含反编译的客户端和游戏资源。
- [ukuq/seer2-server](https://github.com/ukuq/seer2-server)（Java）：只能启动官方客户端并打一场没有任何状态效果的战斗。

用这些关键词没搜到真正的项目：`seerbattle`、`seer-ts`、“赛尔号 对战 模拟器”、“赛尔号 战斗 引擎”。

### 2.3 和你说的“赛尔号写死顺序”的关系

你提到赛尔号里魂印谁先生效是写死在代码里的。从上面几个引擎看，常见做法确实是：每个效果带一个固定的优先级数字，数字相同时按速度或固定顺序。我们的做法不同：优先级相同、而且先后会影响结果时，由双方贼来决定。

## 3. Q宠大乐斗

没有找到官方战斗引擎或招式动画的公开实现。找到的有：

- 自动做日常任务的脚本：[gaoyuanqi/daledou](https://github.com/gaoyuanqi/daledou)（Python，68 星）等好几个。和我们无关。
- [1Milkdeliver/daledou](https://github.com/1Milkdeliver/daledou)：里面有一份玩家整理的 2011 至 2012 年战斗流程（先手 → 武器或技能 → 命中 → 暴击 → 减伤 → 特效 → 扣血）和伤害公式。作者自己标注可信度中等。
- [Shinoakii/nonebot_plugin_daledou](https://github.com/Shinoakii/nonebot_plugin_daledou)（Python）：唯一一个重新实现了战斗逻辑的项目，是聊天机器人插件。自动战斗，只输出文字，有武器、主动技能和 19 个被动技能。
- [JackieMarven/daledou](https://github.com/JackieMarven/daledou)（Cocos Creator）：一个很小的原型，有血条和简单移动。

## 5. 可以直接借用的五个设计

1. **回合拆成一串小动作排队执行，需要问玩家时在两个动作之间停下，没执行完的队列留着。**（Pokémon Showdown）对我们：把“贼”做成一种请求，插在两个冲突动作的前面。
2. **排序规则只有一套，平局只在一个地方处理。**（Pokémon Showdown、simulation-battle-system）对我们：把那一处的随机数换成“发起一次贼”。
3. **固定的时间点；被动效果是登记在时间点上的数据，带优先级。**（两个赛尔号引擎）这样引擎停下来时总是停在一个有名字的点上，存档和恢复都简单。
4. **每个玩家一份带编号的请求；回答很短；保密的部分按玩家分开发。**（Pokémon Showdown、boardgame.io）对我们：贼可以走和选招完全相同的通道，双方都出完之前互相看不到。
5. **客户端只是“战斗记录播放器”。**（Pokémon Showdown）服务器发一串事件，客户端播一条、等动画播完、再播下一条。每次贼的手势也记进去，这样回放和断线重连都能还原。

一点提醒：Pokémon Showdown 和 arcadia-eternity 都不会在一连串被动效果触发到一半时暂停。能在结算正中间停下的例子是 fireplace（把后续动作挂起）和 simulation-battle-system（引擎可以停在任一状态）。这个问题在《03 结算中途暂停》里展开。
