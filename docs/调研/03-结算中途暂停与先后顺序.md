# 03 结算到一半停下来“贼”，以及谁的效果先生效

> 调研时间：2026-11-15。下面提到的每个项目都读了源代码；推断的地方标了“推断”。

## 一句话结论

- 我们的规则有一个别的游戏很少有的要求：**回合结算到一半，要停下来让两个人猜拳，猜完再接着算**。成熟的开源引擎有五种做法。对刘同学现有的 Python 引擎，改动最小、最稳的是“记录裁决、从快照重算”这一种。
- 关于“谁的效果先生效”，别的游戏都是靠固定规则（当前回合玩家优先、按速度、按登场先后、随机）。我们用贼来代替其中“随机”和“固定某一方优先”这两种。
- 你担心的“赛尔号时间点太多”：可以只保留很少的几个时间点，并且不给每个效果排固定的先后号。细节在第 4 节。

## 1. 已经有两个开源引擎内置了“结算中途猜拳”

这说明这个需求是做得到的，而且有现成的参考：

- **无名杀**（[libnoname/noname](https://github.com/libnoname/noname)，网页版三国杀，JavaScript，5266 星）：有一个内置事件叫 `chooseToPSS`，同时向两名玩家弹出猜拳，都选完再继续。
- **ygopro-core**（[Fluorohydride/ygopro-core](https://github.com/Fluorohydride/ygopro-core)，游戏王的规则引擎，C++，429 星）：有一个 `rock_paper_scissors` 函数，先问玩家 0，再问玩家 1，比较结果，打平就重来。

## 2. 五种“暂停再继续”的做法

| 做法 | 谁在用 | 改造现有 Python 引擎的难度 | 断线重连、存档 | 好不好测试 | 主要问题 |
|---|---|---|---|---|---|
| ① 把“算到哪一步了”存成数据（步骤编号或待办队列） | ygopro-core、无名杀的分步写法、Pokémon Showdown 的动作队列 | 难。每个可能暂停的函数都要拆成几步，函数里的临时变量都要搬进局面数据。只在“两个动作之间”暂停的粗粒度版本要便宜得多 | 最好。局面就是普通数据，重连只要把未完成的请求重发一次 | 好 | 写起来啰嗦，步骤号容易写错 |
| ② 协程：函数执行到一半“交出一个请求”，拿到答案后从原地继续 | 无名杀的新写法、ygopro 的卡片脚本 | 中等。从“结算回合”到“可能要问玩家”之间的每一层函数都要改写 | 进程不重启时重连容易。但 Python 的这种暂停状态没法存盘，服务器一重启这一回合就丢了 | 很好 | 少写一个关键字，函数就会悄悄不执行 |
| ③ 每个房间一条线程，问玩家时整条线程卡住等 | 太阳神三国杀、XMage、Forge | 最容易。把掷随机数换成“卡住等回答” | 不能存档，重启房间就没了 | 差。测试要用别的线程假扮玩家 | 线程、锁、超时都容易出错 |
| ④ **记录裁决，从快照重算**：结算前先存一份局面；算到需要贼的地方，如果还没有结果，就放弃这次计算、回到快照、去问玩家；拿到结果后记下来，从快照重新算一遍，这次算到那里就直接用记下的结果 | OpenSpiel（把整局存成动作序列）的思路；Pokémon Showdown 的整局回放 | **容易**。前提是引擎完全可重现（同样的输入一定得到同样的结果）。只要把每个“掷随机数”换成“取下一个已记录的裁决，没有就报告需要输入” | **很好**。存一份快照加一小串裁决就够 | **很好**。一个测试就是一串裁决；出了问题可以原样重放 | 引擎里不能有不受控的随机；战斗记录只能取最后一次计算的；每回合贼的次数越多，重算次数越多（我们这里很少，不是问题） |
| ⑤ 结算开始前就让双方先把拳出好 | — | 极易 | 极易 | 极易 | 不知道这回合到底要贼几次；玩家出拳时不知道在赌什么，丢掉了“结算到一半突然要贼”的那种紧张感 |

**建议用第 ④ 种。** 理由：

1. 刘同学的引擎本来就用了带种子的随机数（给同一个种子，每次结果一样），满足“完全可重现”的前提。
2. 不需要重写引擎的结构，只在“掷随机数”和“平局”这几个点上动手。
3. 测试和回放最方便：一局对战 = 初始设置 + 双方每回合的选招 + 每次贼的结果。

需要坦白的一点：我在你叫停之前已经按这个思路动手改了一部分引擎。那部分改动没有提交，现在收在 `git stash` 里。要不要用，等你回答完问题再定。

## 3. 别的游戏怎么决定“同时触发的效果谁先”

| 规则 | 谁在用 |
|---|---|
| 当前回合的玩家的效果先，对手的后；每个玩家自己排自己那几个效果的顺序 | 万智牌（XMage、Forge）；游戏王（必发效果先于可选效果） |
| 从当前玩家开始按座位顺序，再看一个优先级数字；同一个人有多个同级效果时自己选 | 无名杀、太阳神三国杀 |
| 固定的“最先”“最后”两档 | 无名杀、Pokémon Showdown |
| 按登场先后（先上场的先触发） | 炉石传说模拟器 fireplace |
| 先看先制数字，再看速度，最后随机 | Pokémon Showdown、几个赛尔号同人引擎 |
| 后发先至：后放上来的效果先结算，中间留给对方响应的窗口 | 万智牌的“堆叠”、游戏王的“连锁” |
| 受影响的玩家自己选 | 万智牌（多个替换效果冲突时） |
| 引擎主持一次抛硬币或猜拳 | ygopro-core、无名杀 |

我们的“贼”取代的是表里的“随机”和“当前回合玩家优先”。

顺带一个数学事实：猜拳时，只要有一方完全随机出拳，赢、平、输就各是三分之一。所以“贼赢了才能复活”在双方都认真玩的时候正好是三分之一的概率。用贼代替掷骰子，概率没变，变的是玩家的参与感。

## 4. 你担心的问题：能不能避开赛尔号那一堆时间点

先说结论：**时间点可以压到很少，而且可以不给每个效果排固定的先后号。但不能完全没有时间点。**

为什么不能完全没有：你们自己的规则里已经写了几个时间点。

- “回合开始时”：龙王移动对手场景、牛顿选择自己的场景、库巴贼“扔”和“跑”、灵力圣使自动换血。规则文档里连着问了三次“和龙王的关系？”，这正是同一个时间点上谁先的问题。
- “出招时”：防御、平面镜、憋神技、先手封禁。
- “回合结束时”：烧伤、点燃、寄生虫、场景扣血、生机勃勃回血、青铜怪换血。
- “死亡时”：大难不死、库巴死后放射线、灵力圣使死后全场昏睡。

赛尔号让人头疼的地方有两个：时间点分得非常细（几十个）；同一个时间点上谁先生效是按精灵逐个写死的，玩家只能背。

我们可以这样避开：

1. **只保留四个时间点**：回合开始、出招、回合结束、死亡。新加人物时，它的效果只能挂在这四个点上。
2. **不设固定先后号。** 同一个时间点上有两个效果时，引擎先在暗地里把两种先后顺序各算一遍。结果一样，就随便按一个顺序执行，玩家无感。结果不一样，才让双方贼，赢的一方的效果先生效。
3. 这样规则只有一句话：“同一时刻撞上了，而且先后有区别，就贼。” 不需要任何人背表。

要你确认的地方（也收在《待确认问题》里）：

- 是“只在先后会影响结果时才贼”，还是“只要先制相同就一律贼”？前者贼的次数少很多。
- 贼赢的人是“自己的效果先生效”，还是“由他来决定谁先”？有些情况下后手反而有利。
- 一个回合里如果有好几处都要贼，是每处各贼一次，还是贼一次管整个回合？
- 同一方自己的两个效果撞了（比如自己的内功和自己的招），按什么顺序？这种情况不涉及对手，贼不合适，可以让这名玩家自己选。

## 5. 把“概率”也用贼来实现时要注意的事

你举的例子是“三分之一概率复活，贼赢了才算”。猜拳一次的结果是赢、平、输各三分之一，所以：

| 想要的概率 | 可以怎么贼 | 说明 |
|---|---|---|
| 1/3 | 贼一次，赢了才算 | 你举的例子 |
| 2/3 | 贼一次，不输就算 | — |
| 1/2 | 贼到分出胜负为止，赢了算 | 打平重来 |
| 1/4 | 连续两次分胜负的贼都赢 | — |
| 1/8（比如死亡笔记的 12.5%） | 连续三次都赢 | 贼的次数多，会拖慢节奏 |
| 1/10、30% 这类 | 没有自然的贼法 | 只能用随机数，或者把概率改成上面几种 |

规则文档和引擎里出现过的概率有：25%、33%、50%、66%、12.5%、10%。哪些用贼、哪些让电脑掷随机数，需要你定。这也在《待确认问题》里。
